# 06 节假日年度更新（照做即可）

## 先说清楚：为什么不是“全自动”

国务院每年（一般 11 月）发布下一年放假安排，例如：

> 国务院办公厅关于 2027 年部分节假日安排的通知（国办发明电〔2026〕×号）

官方只发布**文字公告**，没有公开的、可以自动读取的 API。所以本项目不做“爬取”，
也不猜；而是把流程做成“**每年一条命令导入，双端立即生效，带版本可追溯**”。

## 每年要做的事（一年一次，约 5 分钟）

### 1. 找到官方通知

打开中国政府网 [gov.cn](https://www.gov.cn) 搜索“2027 年放假安排”，
认准发文机关为“国务院办公厅”，记录文号（如 国办发明电〔2026〕×号）。

### 2. 生成模板（可选）

不需要从零写 JSON，先让工具生成该年模板：

```powershell
node scripts/import-holidays.cjs --template 2027
```

把输出的 JSON 保存为 `holidays-2027.json`，按官方通知修改 `source` 文号和 `rows`。

### 3. 整理成 JSON 文件

新建一个文本文件（例如 `holidays-2027.json`），内容格式如下：

```json
{
  "year": 2027,
  "source": "国务院办公厅 国办发明电〔2026〕x号",
  "rows": [
    { "date": "2027-01-01", "name": "元旦", "type": "holiday" },
    { "date": "2027-01-03", "name": "调休上班", "type": "makeup_workday" },
    { "date": "2027-10-01", "name": "国庆节", "type": "holiday" }
  ]
}
```

规则：

- 放假日期写 `type: "holiday"`，name 写节日名（如“国庆节”）；
- 调休上班日写 `type: "makeup_workday"`，name 写“调休上班”；
- 日期格式必须是 `YYYY-MM-DD`。

### 4. 先校验（推荐）

正式写入前先跑一次校验，只检查不写库：

```powershell
node scripts/import-holidays.cjs holidays-2027.json --dry-run
```

看到 `校验通过，未写入任何数据` 即表示 JSON 合法（会检查日期是否真实存在、
是否属于该年、是否有重复、type 是否合法）。

### 5. 跑导入命令

在项目根目录打开 PowerShell，先加载临时密钥（见 04-开发者操作手册），然后：

```powershell
. .\work\set-env.ps1
node scripts/import-holidays.cjs path\to\holidays-2027.json
```

看到 `完成：新建 39，更新 0，未变化 0` 和验证记录数即为成功。
导入后，两位成员的日历**立即**显示新一年节假日，不需要重新发布小程序。

## 如果政策中途调整（例如临时改调休）

把官方调整后的安排整理进同一个 JSON，重新跑一次即可覆盖（记录版本号 +1）。
想顺带清理“该年份已不再使用的旧记录”，命令末尾加 `--delete-others`。

## 历史记录

`holiday_calendar` 集合里每条记录带：

- `source`：官方文号；
- `version`：版本号（每次变更 +1）；
- `updatedAt`：更新时间。

可以在云开发控制台数据库里查看，作为追溯依据。

## 常见错误

| 现象 | 原因与解决 |
| --- | --- |
| `rows 为空` | JSON 里没有 rows 数组或数组为空 |
| `year 无效` | year 不是 2000~2100 的整数 |
| `校验未通过` | 按提示修正对应日期的格式 / 重复 / type 后再跑 |
| `[失败] ... Table/...` | 集合未创建：先跑 `node scripts/db-bootstrap.cjs` |
| 导入后日历没变化 | 先确认 `year` 写对；再看日历是否已翻到该月 |
