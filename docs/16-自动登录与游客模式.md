# 16 自动登录与游客模式（v1.1.6，方案 B）

> 对应产品目标：①已登录用户进入即用，无需重复登录；②数据只对绑定双人有效，任何入口（含游客模式）不泄露。

## 1. 背景

微信云函数身份（OPENID）由微信在小程序调用云能力时**静默下发**，全程不需要用户点击任何授权按钮；服务端在首次访问业务时也会自动创建 `users` / `user_identities`。

因此“登录”不是真实门槛。旧版本把登录页当作首屏、未绑定用户被挡在登录页，属于产品流程问题，而非技术限制。

## 2. 目标（验收标准）

### 目标 1：进入即用，无需重复登录

- 已绑定空间：打开小程序 → 无感直达完整日历，全程不出现“登录”字样、无任何弹窗。
- 未绑定空间：打开小程序 → 直接进入“游客模式”日历（公共信息），不要求先登录。
- 只有用户在微信侧删除小程序 / 清理缓存后，本地状态才可能重置；重新进入时身份由微信自动恢复，仍无需手动登录（若微信要求重新授权，回到游客模式即可继续使用）。

### 目标 2：数据仅对绑定双人有效

- 游客模式渲染**公共信息**：本地算法（日期、周末、农历、节气）+ 官方节假日/调休（`holiday-public` 公共接口，只返回 date/name/type 等公开字段）。
- 游客模式**不调用任何业务云函数**，不产生后端数据，不携带任何空间参数。
- 未绑定用户调用任何业务云函数（日历、To Do、生理期、菜单、餐厅、纪念日、旅游、回收站、管理）一律返回 `NOT_IN_SPACE` / `NOT_FOUND`。
- 已绑定双人互见全部数据（产品定义）；第三方账号、其他空间、游客均不可见（含图片临时链接）。
- 以上由自动化安全测试持续验证（`npm test`）。

## 3. 实现要点

### 3.1 首屏

- `app.json`：`pages/calendar/index` 提到第一位，登录页不再作为入口。

### 3.2 日历页身份探测

- `onLoad`：静默调用 `SpaceService.mySpace()`。
  - 成功 → 已绑定，走完整日历（现有逻辑）。
  - `NOT_IN_SPACE` → `guestMode = true`，`buildGuestMonth()` 拉取公共节假日（带年月缓存）后渲染公共日历，不请求业务数据。
  - 网络失败 → `guestMode = true` + 顶部“网络异常，点此重试”（本地周末/农历/节气仍显示）。
- `onShow`：已绑定才刷新业务数据；游客模式只重建本地月份。

### 3.3 游客模式 UI

- 顶部：显示“体验模式”说明 + 「创建空间」「加入空间」按钮。
- 快速入口（事项/菜单/行程/旅游/纪念日/生理期）：点击 → 提示“先创建或加入空间” → 进入空间选择页。
- 图例区替换为“体验模式”说明卡（公共日历范围说明 + 隐私承诺）。
- 空状态提示“创建空间后，这里会记录你们的一天”。

### 3.4 创建/加入空间

- 游客从日历进入 `pages/space/index`（创建 or 加入二选一）。
- 提交创建/加入时服务端自动建号（`resolveIdentity`），用户无感；成功即回到完整日历。

### 3.5 新增云函数 holiday-public（方案 B）

- 位置：`cloudfunctions/holiday-public`，入口 `src/index.ts`。
- 行为：接收 year/month，返回当月 `holiday_calendar` 公共安排；**不校验空间身份**（节假日本属公开数据）。
- 边界：仅返回 `date / name / type / isHoliday / isWorkday / isMakeupWorkday` 公共字段；`toHolidayView` 负责字段裁剪，绝不含私人数据。

## 4. 安全边界（不因本改动放宽）

- 游客模式前端不携带任何空间参数，不请求业务接口。
- 服务端身份校验、`spaceId + recordId` 双重限定、ADMINONLY 数据库权限均不变。
- 新增测试：
  - 未绑定用户调用 `CalendarService.getMonth` → `NOT_IN_SPACE`。
  - `holiday-public` 服务层不依赖空间身份，且返回对象仅含公共字段。
